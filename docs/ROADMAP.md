# Prioritized roadmap

These phases use the current audit request's order. Historical root documents saying phases 1–8 code exists are not acceptance evidence.

| Phase | Work | Exit criteria |
| --- | --- | --- |
| 1 — audit | repository/feature/security review; architecture/cost/schema proposal; small admission-control fix | evidence-based docs, executed baseline/regression tests, reviewed commit; no production readiness claim |
| 2 — AI gateway and accounting | immutable Decimal price/cost/credit ledger, PostgreSQL integration harness, provider/model capability registry, DeepSeek/Ollama adapters first, budgets and reconciliation | exact concurrent reserve/settle/refund/idempotency and unknown-outcome tests; unsupported model/task rejected; no unapproved escalation |
| 3 — identity/plans/license | tenant users/roles, authoritative employee/model/limits, configurable three-plan catalog, explicit subscription states, device revoke/deactivate, offline policy | cross-tenant/role/device/expiry/plan-mode tests; UI derives trusted entitlements; legacy balances/plans safely reconciled |
| 4 — pilot workflow | PO extraction review, catalog validation, Decimal totals, mapped CSV/XLSX, named approval and one tested connector/export | complete fixture workflow and change/replay/error tests; no general ERP claim |
| 5 — payment/operations | signed provider webhooks and lifecycle acceptance, service quotations, signed Windows install/update, actual VPS/PostgreSQL backup/monitoring rehearsal | merchant/provider and clean-Windows evidence, off-server restore/rollback drill; explicit production deployment approval |
| 6 — five pilots | controlled scope, load/performance tuning, support and economics metrics | measured completion/correction/time/cost/errors/satisfaction; resolved incidents and agreed commercial acceptance |

Gemini/Claude, multimodal and advanced models follow verified capabilities, consent and accounting, not merely a configured URL. Full economics dashboard follows reliable revenue/cost/labor data. Multi-server infrastructure follows measured need. Do not make a destructive data migration, live charge, paid infrastructure purchase or production rollout as part of Phase 1.
