# 0.9.6：云端逐条确认与发送

用户反馈：已经点击同意，但仍被要求再次同意。旧界面把确认框放在聊天区上方，每次尝试后（包括失败）清空它，同时允许未确认时继续点击发送。原来的界面测试能验证正常勾选时请求携带 true，但无法从截图还原客户那次请求的实际字段。不能据此断言客户没有勾选，也不能认定 DeepSeek 账户已连通。

## 本次更改

- 云端聊天不再使用独立、远离输入框的勾选框。输入框旁的按钮明确写 **同意云端处理并发送**；起草回复时写 **同意云端处理并起草**。
- 按钮旁说明会把本条消息及所选助理的工作说明发送给已配置云端，可能产生 API 费用。仅这次明确提交携带 `cloud_consent: true`，不保存长期授权，不自动发起下一条消息。
- 没有确认按钮作为提交来源的隐式表单提交不会发出云端请求。键盘激活确认按钮可以正常提交。
- 同步发送锁阻止快速重复点击造成重复请求；请求期间禁止编辑当前输入，避免成功回调清空新输入的内容。
- 失败保留文本。下一次仍由用户点击同一确认按钮，不需要恢复被清掉的隐藏勾选状态，也不自动重试。
- 私密资料配合 Cloud-only 时禁止提交，显示选择本地模式的提示；本地提交不携带云端许可。
- 查询云端用量估算也有单独明确的确认按钮。估算不授权聊天，不会自动生成回答。
- 若客户端已构造 `cloud_consent: true`，服务仍返回许可拒绝，显示“本次请求已提交云端许可，但服务仍拒绝该许可”，避免再次断言用户未勾选。保留文本、当前模式及模型供排查。
- 云端未启用、价格未确认、缺少 Key / 模型的错误增加中英文操作说明。

后端许可、组织策略、价格确认、预算、授权、私密资料限制及电脑操作审批均未放宽。没有修改数据库结构或密钥名称，API-PREVIEW 0.9.5 可覆盖更新并沿用已有工作区。
