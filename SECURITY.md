# Security

Keep the API bound to loopback. Use a fresh random NIGHTBREW_SESSION_TOKEN for each session. Health is public; history and chat require bearer authentication. Renderer sandbox, context isolation and disabled Node access are enabled. New windows, navigation and permission requests are denied. Provider errors are sanitized; cloud requires HTTPS and explicit per-message consent. Redirects are disabled to avoid forwarding credentials.

No unrestricted shell execution, file tools or external actions are implemented. Future consequential actions must require human approval. Local SQLite is not encrypted. Backend environment keys are a development mechanism, not Windows Credential Manager integration. No entitlement or payment claim can derive from local data. A security review, CSP hardening, signing, secure updates and Windows Credential Manager remain release requirements.

Phase 2–3 additions: cloud routing is denied for private data; per-request consent plus global permission and local budgets are enforced. Credit reservations use SQLite write transactions. Failed/unknown billed calls retain estimated charges; pricing must be entered and verified by the operator. These are development controls, not authoritative paid entitlements. BYOK uses Windows Credential Manager on Windows, with no plaintext fallback; this Windows path remains unverified.

File access is restricted to registered opaque IDs under the data directory. Formula execution, macros, arbitrary file paths and AI-generated shell commands are unavailable. Document extraction returns untrusted text, not instructions. Task approval is bound to immutable stored payloads, single use, and never auto-approved by a model. Cancellation/deadlines are cooperative: native parsers and already dispatched remote calls cannot be forcibly undone. Native parser process isolation and malware scanning remain release requirements. Authenticated users of this single-user desktop session are administrators; multi-user tenant roles are not implemented.
