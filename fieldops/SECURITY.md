# Security and safety

Implemented: salted scrypt passwords; random 48-byte bearer sessions stored as hashes on the server with 24-hour expiry and logout revocation; native secure storage for mobile sessions; authenticated API routes; server-derived tenant filters and composite foreign references; engineer assignment boundaries; viewer read-only controls; role-gated company/user administration and closing; transactional optimistic revisions; fingerprinted idempotent note replay; escaped PDF text; bounded request/response sizes; audit metadata; in-process bounded request/login/report rate limits; HTTPS mobile origin validation and disabled redirects.

There is no default password, public company bootstrap, arbitrary shell execution, public evidence bucket or paid AI call. The owner provisioning CLI runs on the server and asks for its password without echo. A development Android build may explicitly allow loopback/emulator HTTP; arbitrary public HTTP remains rejected. Release builds require HTTPS. Do not disable TLS verification.

Operational requirements: serve only behind correctly configured HTTPS, keep SQLite and backups outside public directories, restrict file permissions, encrypt devices/disks/backups, configure trusted proxy handling and patch dependencies. Mobile SQLite is app-private but NOT independently database-encrypted; sensitive sites may require MDM, stronger encrypted storage and remote wipe before commercial deployment. Rooted/jailbroken device protections, certificate pinning, MFA/password recovery, session management UI, centralized rate limits, formal penetration review and retention deletion jobs are not yet implemented. App-private OS backup behavior must be reviewed before site evidence is added. Logs must not include bearer headers/passwords or site-note bodies.

Phase 1 generates no technical diagnosis. Its reports preserve engineer-entered observations and mark missing facts for confirmation. Never infer a successful repair, used part, measurement, customer acknowledgment or signature. Hazardous work requires qualified personnel and verified manufacturer procedures. Do not bypass protective systems. Manual/voice/photo processing requires later authorization, parser hardening and explicit cloud consent.

Do not deploy the development APK, API explorer or mock pricing as a finished commercial service. Authentication and company separation are implemented groundwork, not a security certification.
