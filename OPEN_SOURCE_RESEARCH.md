## Repository exceptions and platform scope

- The requested `theorchard/openpyxl` repository returns 404. The installed `openpyxl` 3.1.5 distribution declares MIT in [PyPI metadata](https://pypi.org/project/openpyxl/3.1.5/); canonical project hosting differs from the stale repository. Its current upstream commit activity was not verified in this environment.
- ReportLab GitHub source above is explicitly a mirror, not proof that the mirror is canonical. The installed distribution and fonts have their own retained license notices.
- SQLite is used through Python's standard library, with no separate service. Its upstream public-domain policy is documented at https://www.sqlite.org/copyright.html; that upstream page was not newly fetched under the current network policy. Workload/locking, file permissions, backups and migration remain application responsibilities.
- Microsoft Windows UI Automation is an OS API, not an open-source dependency to copy. It requires an actual Windows interactive session. The Windows API documentation was not newly retrieved; pywinauto is the pinned adapter.
- Desktop JS frameworks and business parsers support Windows and macOS in the current application; actual packaged tests remain the evidence. pywinauto/UFO are Windows-specific; hosted service projects are not native desktop redistributables. Optional server/platform compatibility must be tested before adoption.
- TypeScript's inspected license is Apache-2.0, not MIT; the previous audit grouping was too broad. Open Interpreter's currently inspected default-branch license is Apache-2.0; this does not retroactively establish the license of other releases.

## Implementation selection

Retain Electron/React/TypeScript/Vite/Tailwind, FastAPI/SQLite, deterministic document libraries, a small explicit task state machine, Playwright and Windows UIA. Do not embed a general code interpreter or agent framework to produce this GUI. Do not add a vector database, Kubernetes, payment microservice, monitoring server or mandatory GPU infrastructure just for onboarding.

The current task changes customer navigation, real status display, guided prompt templates, role presets and plain-language approval review. Knowledge-base indexing/search, pause/resume of active workflows, verified real-vendor connectors, production signing/notarization, and customer acceptance remain separate work where not already implemented; a menu or guide does not establish those capabilities. Existing connectors stay available across all plans.
